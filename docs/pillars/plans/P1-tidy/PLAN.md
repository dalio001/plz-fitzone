- Top CSS defines dark colour variables, `.logo-plz` lime `#a3e635`, `.btn`, `.card`, `.set-row`, `.modal`/`.modal-content`, `.chips`/`.chip`; spacing/type/radii vary, `.btn` has no minimum height, and several controls override heights to 30–40px. No `:focus-visible` or reduced-motion rule exists.
- `#tab-profile` is one stream: heading → three stats (`#statWorkouts`, `#statVolume`, `#statSets`) → `#myProfileCard`/`#myProfileBody` → `#calendarCard` → `#profileRecordsCard`/`#profileRecords` → anonymous Settings & Data Backup card.
- `renderProfileStats()` updates stats and preference values, calls `renderMyProfile()`, `renderProfileRecords()`, `renderTrainingCalendar()`. Calendar owns `#calendarTitle`, `#calendarGrid`, `#calendarConsistency`, plan copy controls and `#calendarWorkload` with month/all-time chips; workload is currently inside the same card.
- `renderMyProfile()` shows weight unit, goal, experience, height, birthday/age and setup/re-run; `renderProfileRecords()` lists up to eight recently completed exercises, opening `openExerciseProgress(id,'profile')` with existing record definitions.
- Settings controls: `#defaultRestInput`, `#prevScopeSelect`, `#weekStartSelect`, `#dropStepPctSelect`, `#supersetAdvanceCheck`, `#plateBarKgInput`, `#plateBarLbInput`, `#platePlatesKgInput`, `#platePlatesLbInput`; backup/restore uses `exportData()`, `#importInput`/`importData(event)`, `#restoreDoneBanner`, `#undoRestoreBtn` and preview/undo modals. Units currently use global-header `#unitToggleBtn`/`toggleUnit()`.
- `#tab-history` header has Workout History + `goToTrainingCalendar()`; it selects Profile, resets to this month and scrolls to the card. No separate Profile-level records shortcut currently exists; records rows open the exercise-progress modal.
- Exercises: static `#exSearchInput`, `#exMuscleChips`, `#exEquipChips`, `#showHiddenChk`, `#exercisesDirectory`; `renderExercisesTab()` rebuilds chips/results, not the search field. `openExerciseDetail()` calls `renderExerciseDetail()` into `#exDetailBody` in `#exDetailModal`: name/badges, muscles, best/estimated values, recent sessions, then Progress/favourite/edit/delete/unhide actions. No exercise notes editor exists.

## Proposed Profile structure and routing
- Add static `#profileSectionControl` immediately below the Profile heading, sticky at `top:0` inside scrolling `main`, opaque current background, modest stacking level below overlays; three equal-width buttons: **Progress / Records / Settings**, each ≥44px high. Use a labelled button group, `aria-pressed` and `aria-controls`; normal Tab/Enter/Space operation, visible focus.
- Wrap existing blocks once, retaining their IDs: `#profileProgress` contains the stats grid and whole calendar card, consistency, existing plans/copy-week controls and muscle workload; `#profileRecordsSection` contains My records; `#profileSettings` contains My profile, units, all preferences, plates and backup/restore/undo UI. Inactive panels use `hidden` and cannot receive keyboard focus.
- Move the existing `#unitToggleBtn` from the header into a labelled Units row in Settings; keep its ID, `toggleUnit()` handler and KG/LBS display semantics. My profile's weight-unit summary remains read-only; do not duplicate the setting. Keep the header Plates calculator shortcut.
- Add `setProfileSection(section)` to validate `progress|records|settings`, toggle panel visibility and button state without replacing panel HTML. Restore the chosen section on init/Profile entry; data-driven `renderProfileStats()` calls must not reset it.
- The sole storage addition is a UI-only localStorage key `plz_fitzone_profile_section`, holding that allow-listed string; absent/invalid/unreadable → Progress, failed writes → keep the current selection in memory. Wrap reads/writes in try/catch. No `state`/backup/schema field, migration or changes to existing storage keys.
- `goToTrainingCalendar()` selects Progress before showing Profile and scrolling; preserve its current-month behavior and use scroll margin below the sticky control. Records navigation/record-row links select Records first; for existing rows, handle `origin === 'profile'` in `openExerciseProgress()` before opening the unchanged modal. Catalogue/history/workout Progress links retain their current origins and behavior; do not invent new shortcuts.
- Mount all three panels statically; section changes only hide/show them. Keep preference handlers, validation, defaults and save timing. Separate settings hydration from derived refresh in `renderProfileStats()` so `savePlateSettings()`/`setPrevScope()` cannot overwrite another unfinished field. Typing never replaces the Settings/Profile shell, active input or ancestors; commits refresh derived values in place. No new render-on-input/change/blur wiring; search typing updates results without replacing search/chip controls or losing caret/focus/scroll.
