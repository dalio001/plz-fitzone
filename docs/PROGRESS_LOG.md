## 2026-10-17 — Correction after the emulator run: main state mirrored to IndexedDB too, start-up adopts the newer copy, offline strip moved under the header (P0-01), awaiting owner phone check

- Same branch `codex/p0-01-offline`, no new plan. The second emulator test (Pixel 8, airplane mode) confirmed the draft mirror works (tick → force-kill 1 s later → tick restored 3/3 runs) and exposed the **same flush gap in the main state**: seed 12 workouts, start a routine, tick, kill 1–2 s later → on reopen `hevy_clone_state` had history 0 and onboarding showed again, so a workout finished seconds before a kill could vanish from history.
- **Main-state mirror:** `saveState()` now also writes `{ savedAt, json }` — `json` is the **exact localStorage string**, so adopting it is lossless — into the same IndexedDB database (`plz_fitzone_draft` → `drafts` → key `main_state`), in a `{ durability: 'strict' }` transaction when supported. The state object also carries a `savedAt` stamp (metadata only). `pagehide` and hidden `visibilitychange` now flush the **state** as well as the draft (both in `flushDurableState()`), and the two exceptions that write the state directly — `confirmRestore` goes through `saveState()`; `undoLastRestore` keeps writing its exact snapshot bytes to localStorage and mirrors those same bytes with a fresh stamp — both keep working with both copies written.
- **Start-up order (never let a fresh default win):** `startApp()` replaces the bare `init()` call. With IndexedDB available it reads **both** mirror keys first (`Promise.all`, **capped at 500 ms** so a hung/blocked database can never keep the app closed), adopts the main-state mirror when it is newer than localStorage **or** when localStorage is missing/empty/corrupt (writing it back to localStorage before `init()` reads it) and then runs `init()`. Without IndexedDB (file://, private mode, tests) start-up stays synchronous and byte-for-byte as before; `app.api.bootReady` lets a test wait. Mirror writes are suppressed until that read settles and until `init()` has run (`mainMirrorBootPending`/`appBooted`), so nothing this build writes can overwrite a newer mirror while starting, and a `pagehide` during the start-up window can no longer stamp a default state over the saved one. If the 500 ms cap wins, the late answer is ignored — the app is already running on localStorage and its writes would be newer anyway (documented trade-off; a healthy read is ~10–50 ms).
- **Offline pill moved to the top:** it is no longer a `position:fixed` overlay at the bottom (it covered the Continue and bottom-nav buttons). It is now a **normal-flow strip directly under the header** (`max-height:36px`, `overflow:hidden`, 8 px padding, 13 px text, `pointer-events:none`), so it can never cover a button; `updateOfflinePill()` is unchanged (shows only while `navigator.onLine === false`).
- Checks: `tests/offline.test.mjs` grew to 17 tests — the 7 new ones are `main-state-mirror-written-on-save`, `start-prefers-newer-mirror-when-local-is-older`, `start-uses-mirror-when-local-missing`, `fresh-default-never-overwrites-newer-mirror` (corrupt local copy loses), `restore-writes-both` (restore *and* undo), `offline-pill-is-at-top` (after `</header>`, before `<main>`, no `position:fixed`/`bottom`/`z-index`, ≤36 px, no taps) and `pre-boot flush never writes a default state over the saved one`.
